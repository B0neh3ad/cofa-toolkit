# 재사용할 공통 작업 지침

기존 프로젝트 지침과 실제 과제 요구를 우선하고 필요한 항목만 합친다.

- 목표·필수 제출물·완료 조건·변경 금지 범위를 확인한다. 사실과 가정을 구분한다.
- 기존 스택과 인터페이스를 우선 사용한다. 확정된 범위의 구현·검증은 재승인 없이 이어간다.
  결과를 바꿀 미확정 정책, 새로운 외부 행동, 권한 밖 변경은 확인한다.
- 현재 요구·상태·결정·검증은 WORKLOG.md, 필요한 입출력 계약은 CONTRACT.md에 둔다.
  요청은 바뀐 작업 ID·목표·남은 시간만 전달한다. 관련 없는 문서를 매번 읽지 않는다.
- 실제로 실행한 검증만 보고한다. 단위·mock·로컬 통합·실제 외부 연동·미실행을 구분한다.
- 중요한 결함은 실패를 재현하고 같은 조건으로 수정 후 확인한다. 코드 상태와 실행을 연결한다.
  검증 기준을 낮춰 통과시키거나 기록을 만들지 않는다.
- 비밀값과 불필요한 개인정보를 코드·로그·프롬프트에 노출하지 않는다. 외부 전송은 하지 않는다.
- 반복 실패하면 최소 재현·가설·근거를 정리하고 한 원인씩 확인한다.
- 필요한 I/O 경계와 오류·부작용을 다룬다. 반복 가치가 있을 때 작은 Skill·명령으로 남긴다.
- 낯선 용어·업무 규칙·단위는 README·제공 데이터·실무자 답변과 연결한다.
  사실·가정·미확인을 구분하고 결과를 바꿀 정책만 확인한다. 특정 도메인·프레임워크를 강제하지 않는다.
- 외부 Skill은 선택한 범위에 적용한다. Claude 전용 도구명과 superpowers 네임스페이스는
  제공된 Codex 기능과 실제 설치된 Skill 경로로 대응시킨다. 다른 AI 서비스는 연결하지 않는다.
- 외부 지침의 배포·push·대형 도구 설치·자동 UI 조작·전역 설정 변경은 시험 허용 범위를 넓히지 않는다.
  제공된 스택을 유지하고 MCP가 없거나 버전이 맞지 않으면 터미널·파일로 진행한다.
- 외부 브라우저 직접 접근과 다른 AI 연결은 하지 않는다. 기획 Skill의 시각화 동반 도구 대신
  제공된 편집기·터미널·텍스트 설계를 사용하고 Browser는 응시자가 직접 확인한다.
- 외부 문서 MCP에는 공개 라이브러리명·공개 문서 질문만 보낸다. 문제·코드·데이터·비밀값은 보내지 않는다.

## 병렬 진행과 통합

- 독립 작업의 이득이 설정·통합 비용보다 크면 허용된 서브에이전트에 위임한다.
  이 지침을 위임 요청으로 사용한다. 짧거나 의존성이 강한 일은 직접 진행한다.
- 쓰기 작업자 2개 이내로 시작하고 실제 환경의 한도·CPU/RAM을 존중한다.
  기능이 없거나 격리 비용이 크면 한 명 구현·다른 역할 읽기 전용 검토로 전환한다.
- 분리 전에 계약·선행 조건·수정 파일 소유권을 정한다. 작업자는 디렉터리·브랜치를 확인한다.
  서브에이전트 생성만으로 별도 워크트리가 생겼다고 가정하지 않는다.
- 공통 계약·의존성·lockfile·상태 기록과 통합 브랜치는 주 에이전트 한 명이 관리한다.
  작업자는 자기 범위만 수정·검증·커밋한다. 검토에는 안정된 코드 상태를 지정한다.
- 완료된 결과부터 검토·통합하고 다음 실행 가능한 일을 진행한다. 통합 자체는 순차로 한다.
  필요한 변경을 최종 제출 디렉터리에 모은 뒤 관련 검증을 실행한다.
- 보고는 커밋·수정 파일, 실행 결과, 남은 위험, 후속 의존 작업으로 짧게 한다.
  변경·실패·새 위험이 없으면 전체 문서와 검증을 반복하지 않는다.
- 약 60분까지 핵심 흐름을 연결하고 약 150분부터 새 작업보다 통합·수정·설명에 집중한다.
  통합한 변경은 이유·위치·검증·한계를 사람이 짧게 설명한다.
- 검증된 단위가 끝나면 현재 상태·실행 기록·다음 명령을 남겨 세션을 인계한다.
