# 결과물 사용 안내 예시

## 목적과 완료 범위

해결한 업무와 지원 범위를 실제 구현에 맞게 작성한다.

## 실행 방법

필요한 버전, 설치 명령, 실행 명령, 입출력 경로를 적는다.
웹 서비스라면 포트와 접근 방법, 실행을 유지할 터미널을 적는다.
실행하지 않은 명령을 검증된 명령처럼 기재하지 않는다.

## 구성과 동작

주요 파일 3~5개와 입력부터 출력까지의 흐름을 설명한다.
오류 처리, 상태 저장, 중요한 정책이 있는 위치를 적는다.
외부 의존성이 있으면 경계와 오류 전파, 부작용의 중복 실행 방지 정책을 설명한다.
계층 이름이나 다이어그램만으로 격리가 잘되었다고 주장하지 않는다.

## 검증 결과

필수 요구사항별 확인 방법과 실제 결과를 적고 작업 기록을 연결한다.
단위·mock·로컬 통합·실제 외부 연동·직접 확인을 구분한다.
실제 외부 연동을 하지 못했다면 이유와 검증하지 못한 동작을 적는다.
커밋이나 파일 상태, 실행 ID를 남겨 설명이 어느 코드에 해당하는지 확인할 수 있게 한다.

## 한계

미구현 요구, 실패 조건, 데이터 크기나 외부 의존성의 제한을 적는다.
개선 계획과 현재 구현을 구분한다.
