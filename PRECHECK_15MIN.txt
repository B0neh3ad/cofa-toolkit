15분 사전 체험 체크리스트 — AGENTS.md를 위한 환경 확인

목표: 구현을 많이 해보는 것이 아니라, 본시험 첫 실행을 막을 조건을 확인한다.
각 결과는 [성공 / 불가(오류) / 미확인]과 실제 명령·경로로 기록한다.
체험 문제의 스택·경로·실행 명령이 본시험에도 같다고 가정하지 않는다.
이 문서는 준비 제안이다. 실제 화면과 최신 시험 안내가 우선한다.

시작 버튼을 누르기 전
[ ] 전원·휴대폰 충전·웹캠·Proctor·전체 화면 공유·촬영 구도를 준비한다.
[ ] 이 체크리스트를 읽고 사용할 공개 저장소 URL과 커밋을 미리 정한다.
    로컬 ZIP을 준비했다는 사실만으로 플랫폼 반입이 된 것은 아니다.
[ ] 선택 기능에서 30~60초 이상 막히면 원인과 상태만 적고 다음으로 넘어간다.
    접속·감독·기본 실행 장애는 우선 해결하거나 문제 신고한다.

0~2분 — 파일과 화면, 도움 요청
[ ] README와 기존 AGENTS.md 등 지침을 찾고 터미널에서 pwd로 루트를 확인한다.
[ ] 연습용 새 파일을 작성·저장하고 '저장됨' 표시와 터미널의 내용을 대조한다.
[ ] 새 터미널/분할을 열어 Codex·서버·검증용 탭을 구분할 수 있는지 확인한다.
[ ] Cofa Helper에 먼저 질문을 보내고 나머지 점검을 진행한다.
    1. 체험 파일·설정·Codex 세션이 본시험에 유지되는가?
    2. 본시험 제출 대상 루트는 어디인가? 별도 worktree 결과는 어떻게 포함되는가?
    답이 없으면 '미확인'이다. 보존이나 제출 범위를 추정하지 않는다.

2~5분 — Codex와 기본 실행
[ ] codex 실행 → /status로 모델·권한, /model로 허용 모델, /help로 실제 기능 확인.
    제공 버전은 업데이트하지 않는다. 개인 API 키를 넣지 않는다.
[ ] 필요한 것만 실행: codex --version, python3 --version, node --version,
    git --version. 해당 프로젝트에서 쓰는 패키지 관리자가 있으면 그 버전도 확인.
    명령이 없다고 설치부터 하지 말고 사용 가능한 실행 경로를 확인한다.
[ ] 짧은 요청으로 README 읽기 → 연습 파일 1개 수정 → 실제 명령 실행까지 확인한다.
    응답 지연·승인 대기·실행 오류를 구분하고, 필요한 승인 화면을 한 번 경험한다.
[ ] 기존 AGENTS 지침의 적용 여부를 관찰 가능한 규칙으로 확인한다.
    Codex의 자기보고만으로 자동 발견을 증명했다고 기록하지 않는다.
    필요하면 연습 전용 디렉터리에 무해한 응답 표식 지침을 만들고 그 위치에서
    새 Codex 세션을 시작해 확인한다. 기존 지침을 덮어쓰지 않는다.
    직접 '파일을 읽어줘'로 준수한 결과와 자동 발견 결과는 구분한다.

5~7분 — 준비 자료 반입
[ ] 준비한 작은 공개 toolkit 저장소를 허용된 플랫폼 터미널에서 clone한다.
    위치·커밋을 확인하고 사용할 파일 1개를 읽거나 최소 명령 1개만 실행한다.
    가져올 저장소가 아직 없다면 이 시간은 필수 실행 확인에 쓴다.
[ ] clone의 성공과 패키지 설치·외부 API 접근 가능 여부를 구분한다.
    사용하지 않을 MCP/Plugin 전체를 설치하지 않는다.
    쓸 MCP가 이미 정해져 있다면 제공된 설정 화면과 연결 상태만 우선 확인한다.

7~10분 — Browser 미리보기
[ ] 준비한 toolkit을 반입했다면 practice/browser/README.md의 완성된 작은 앱으로
    설치 없이 실행·포트·버튼·새로고침 후 보존을 확인할 수 있다.
[ ] 연습 프로젝트의 기존 실행 명령을 우선 사용해 서버를 시작한다.
    없다면 연습 전용 폴더의 작은 페이지로 연결만 확인한다.
    비밀 파일이 있는 작업 공간 전체를 정적 서버로 공개하지 않는다.
[ ] 0.0.0.0 바인딩, 실제 포트, 경로 /로 플랫폼 Browser에 연결한다.
    3000은 예시다. 서버가 출력한 포트를 사용한다.
[ ] 버튼·입력·새로고침을 직접 확인하고 서버 탭을 유지한 채 다른 터미널을 쓴다.
    연결 실패 시 서버 오류/종료 → 포트 → 바인딩 → 경로 순서로 본다.
    외부 터널이나 Computer Use로 우회하지 않는다.

10~12분 — 병렬 작업, 시간이 남을 때만
[ ] /help 등에 제공된 subagent 기능이 보이면 작은 읽기 전용 작업 2개로 확인한다.
    요청 예: "서브에이전트 2개로 동시에 확인해줘. A는 README의 실행 명령,
    B는 테스트 파일과 테스트 명령을 찾아 각각 두 줄로 보고해줘. 파일은 수정하지 마."
    실제 작업자 상태가 겹쳐 실행됐는지 확인한다. 선언만으로 성공 처리하지 않는다.
[ ] 별도 worktree가 필요한 전략이면 제공 기능과 허용 경로를 확인한다.
    이미 커밋된 작은 연습 저장소가 있고 여유가 있을 때만 생성까지 시험한다.
    git worktree list 성공은 생성 권한이나 제출 포함을 증명하지 않는다.
    subagent 생성만으로 별도 worktree가 생기지도 않는다.
[ ] 어렵거나 미확인이면 기본 전략을 '한 명 구현 + 읽기 전용 검토'로 둔다.
    subagent도 없으면 한 세션에서 구현과 검토를 순차로 진행한다.

12~15분 — 기록과 종료
[ ] templates/ENVIRONMENT.md 양식에 성공한 명령·경로·오류·미확인을 간결히 남긴다.
[ ] Helper 답변을 반영하고, 체험→본시험 유지 여부가 미확인이면 재확인을 계획한다.
    환경 기록의 보존·반입 방법도 허용 범위를 확인한다. 문제·코드·데이터를 외부로 보내지 않는다.
[ ] 저장 상태와 감독 연결을 다시 보고 '체험 종료' 흐름을 확인한다.
    이어지는 예시 서술형에서 타이머·다음 문항·이전 문항 이동 제한을 경험한다.
    예시 문항 전체 풀이와 생성 대기가 이 15분 안에 끝난다고 가정하지 않는다.
    AI 사용 금지 단계로 전환되면 AI를 사용하지 않고 본인이 직접 입력한다.

AGENTS.md에는 확인된 반복 규칙만
- 사용할 런타임/패키지 관리자, 실제 과제의 실행·테스트 명령
- 작업 루트와 최종 제출 경로, 서버 바인딩과 미리보기 방식
- 허용 모델/승인 처리, 확인된 병렬 기능과 실패 시 대안
- 공개 자료 반입 위치, 기존 지침 우선, 버전/관리 설정 유지
관찰 로그와 일시적 오류는 ENVIRONMENT.md에 두고 지침을 길게 만들지 않는다.
체험 명령은 체험 관찰값이다. 본시험 README를 읽은 뒤 실제 과제 명령으로 확정한다.
Codex는 시작할 때 지침을 구성하므로 새 AGENTS 규칙은 새 세션에서 확인하거나
현재 세션에 해당 파일을 명시적으로 읽게 한다. 자동 재적용을 가정하지 않는다.

제한된 시간에 생략해도 되는 것
- 모델별 장문 벤치마크, 툴킷 전체 테스트, 전체 worktree 실습
- 새 프레임워크/대형 MCP 설치, 다수 Skill 일괄 설치, 전역 설정 변경
- 고급 기능을 쓰기 위한 제공 Codex 업그레이드나 제한 우회

첫 짧은 요청 예시
"사전 체험 중이야. 2분 안에 기존 지침·README·작업 루트를 확인하고, 필요한
런타임 버전과 README의 실행/테스트 명령을 정리해줘. 연습 전용 파일 하나로
쓰기와 실제 실행을 확인하되 기존 파일은 보존해줘. 성공·오류·미확인을 구분해
ENVIRONMENT.md에 짧게 남겨줘. 설치·업데이트·관리 설정 변경은 하지 말고
비밀값이나 전체 환경변수는 출력하지 마. 화면·감독 연결은 내가 직접 확인할게."

위 요청으로 확인하지 않은 GUI·네트워크·subagent 기능을 성공으로 기록하면 안 된다.
