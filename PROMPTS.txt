아래 요청문의 목표, 경로, 완료 조건을 실제 과제에 맞게 바꾸어 사용합니다.

1. 시작과 범위 확인
README와 기존 지침, 주요 파일, 실행 환경을 확인해줘. 아직 코드를 바꾸지 말고
목표, 필수 제출물, 변경 금지 조건, 실행 명령, 중요한 미확인 사항을 요약해줘.
확인된 사실과 가정을 나누고, 완료 조건을 관찰 가능한 입력과 출력으로 적어줘.
계획은 현재 남은 시간 안에 끝낼 수 있는 크기로 제안해줘.

2. 업무 맥락 질문 준비
결과를 바꿀 수 있는 질문만 최대 3개 뽑아줘. 각 질문마다 답에 따라
어떤 구현이나 검증 기준이 달라지는지 적어줘. 필수조건은 README와 대조해줘.

3. 범위를 정한 구현
합의한 R1을 먼저 구현해줘. 유지할 API와 수정 가능한 파일은 방금 정한 범위를 따른다.
작은 단위로 구현하고 정상 경로 및 관련 실패 경로를 실제로 실행해줘.
변경 이유, 실행한 확인, 실제 결과, 남은 한계를 보고해줘.

4. 읽기 전용 서브에이전트 연습
서브에이전트 2개를 명시적으로 사용해 병렬로 검토해줘.
A는 요구사항과 구현의 불일치를, B는 검증 누락과 실패 입력을 조사한다.
둘 다 파일 수정은 하지 않는다. 각 결과는 중요도, 파일 위치, 재현 입력,
기대 결과와 실제 결과, 미확인 사항 형식으로 받는다.
두 결과가 모두 오면 네가 충돌이나 오탐을 확인하고 수정 우선순위를 정리해줘.
서브에이전트 기능을 사용할 수 없다면 이유를 알리고 같은 검토를 순차로 수행해줘.

5. 수정 권한을 분리하는 위임 예시
구현 정책과 함수 인터페이스를 먼저 확정한다. 이미 정해진 내용은 재승인 없이 사용한다.
결과를 바꿀 미확정 정책만 확인하고 독립된 작업은 계속 진행한다.
A는 src/의 지정 파일, B는 tests/의 지정 파일만 수정한다.
같은 파일이나 의존성 설정을 함께 수정하지 않는다.
주 에이전트는 합친 결과를 실제로 실행하고 문서와 동작이 일치하는지 확인한다.
분리하기 어려운 작은 작업이면 한 에이전트로 진행한다.

6. 검증 요청
필수 완료 조건을 기준으로 최종 상태를 검증해줘. 실제 명령과 종료 코드,
기대 결과와 실제 결과를 남겨줘. 실패와 미실행을 숨기지 말고
현재 제출을 막는 문제와 이후 개선을 구분해줘. 외부 전송은 하지 마.

7. 반복 실패 시 방향 조정
지금까지 확인한 사실, 실패를 재현하는 최소 입력, 현재 가설을 정리해줘.
최근 수정에서 변한 가정이 있는지 확인하고 한 번에 한 원인만 검증해줘.
같은 접근이 반복 실패하면 남은 시간을 기준으로 더 작은 해결책을 제시해줘.

8. 설명 연습
현재 코드와 문서를 근거로 내가 설명하는 연습을 하자.
구조 선택, 실제 데이터 흐름, 검증 근거, 실패 조건에 관해 한 문항씩 물어봐줘.
내가 답한 뒤에만 실제 파일과 대조해 피드백해줘.
이것은 AI 사용이 허용되는 준비 단계에서만 한다.

9. 도메인에 맞는 작은 Skill
실제 과제에서 반복할 규칙이나 검증이 무엇인지 먼저 찾아줘.
기존 도구로 충분하면 그것을 쓰고, 반복 가치가 있을 때만
입력 스키마·업무 규칙·중요한 반례·실행 명령을 담은 작은 Skill로 만들어줘.
만든 파일 수 대신 실제 사용과 발견·수정·검증 효과를 기록해줘.

10. 실패→수정→같은 검증
이 결함의 재현 검증을 먼저 실행해 실제로 실패하는지 확인해줘.
테스트·입력·기대값을 유지하고 구현을 고친 뒤 같은 검증을 실행해줘.
코드 상태와 두 실행 기록, 원인과 수정 함수를 연결해 보고해줘.
기준을 바꾸어야 한다면 변경 이유를 밝히고 바뀐 검증으로 새 기준선을 만들어줘.

11. 새 세션에서 재개
최신 WORKLOG와 실제 파일을 읽고 확정 정책, 마지막으로 확인한 상태,
아직 미검증인 부분과 다음 한 작업을 정리해줘. 오래된 기록은 식별해줘.
관련 핵심 검증을 실행해 현재 상태를 확인한 뒤 허용된 범위의 다음 작업을 진행해줘.

12. 문서·협업 주장 대조
협업 문서의 중요한 주장마다 실제 요청이나 검토 기록, 반영 파일·함수,
실행 근거가 있는지 대조해줘. 없는 근거를 채워 만들지 말고 미확인으로 표시해줘.
단위·mock·로컬 통합·실제 외부 연동을 구분하고, 실제 호출 여부는 코드 경로와
민감값을 제외한 실행 증거로 확인해줘. 외부 전송은 하지 마.

13. 외부 경계와 부작용 검토
실제 외부 I/O가 있는 부분만 대상으로 업무 규칙과의 경계를 살펴봐줘.
시간 초과·잘못된 응답·호출 제한을 삼키는지, 재시도가 부작용을 중복시키는지,
필요한 원자성이나 동시성 정책이 있는지 재현 가능한 근거로 검토해줘.
단순 작업에 계층을 추가하는 것 자체를 목표로 삼지 마.

14. 반복 요청 줄이기
공통 지침은 AGENTS.md에 두고 이후 요청에서는 작업 ID와 달라진 조건만 전달하자.
현재 상태는 WORKLOG에 유지하고 필요한 계약과 관련 파일만 읽어줘.
모든 프롬프트·도구 문서를 AGENTS에 한꺼번에 넣지는 마.

15. 준비된 작업부터 진행
선행 조건과 수정 파일을 기준으로 실행 가능한 작업을 골라 병렬로 진행해줘.
완료된 결과는 다른 작업자를 기다리지 말고 검토·통합해줘.
통합 브랜치의 변경과 공용 기록 갱신은 네가 순차로 맡고, 전체 검증은 통합 상태에서 실행해줘.

16. 짧은 후속 요청
T2 진행. 계약 v1 유지. 작업판의 수정 범위 준수. 남은 시간 95분.

17. 인계 시점 잡기
현재 검증된 단위가 끝나면 최신 상태·실행 기록·다음 한 명령을 인계 문서에 남겨줘.
작업자가 실행 중이면 위치와 브랜치, 완료 커밋과 통합 여부를 포함해줘.
오래 걸리는 명령 실행·충돌 해결 도중의 불완전한 상태는 먼저 명시해줘.
