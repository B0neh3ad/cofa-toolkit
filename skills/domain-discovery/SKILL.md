# 낯선 도메인의 요구와 근거 정리

목표는 구현을 바꿀 업무 의미를 빠르게 확정하는 것이다. 일반적인 도메인 지식을
현재 과제의 규칙으로 단정하지 않는다. 명확한 README를 다시 장시간 인터뷰하지 않는다.

1. README, 기존 지침, 데이터 사전·스키마, 작은 대표 입력, 기존 실행 결과를 확인한다.
   요구된 문제와 제안 솔루션을 분리하고 필수 출력·완료 조건·금지 변경을 뽑는다.
2. 생소한 용어를 원문·이 과제에서의 의미·단위·근거 위치로 정리한다.
   필드 이름만 보고 의미를 추정하지 않는다. 특히 상태 전이, 분모, 기준 시점,
   누적/증분, 금액/단가, 수량/비율, 이벤트 시각/처리 시각을 확인한다.
3. 확인된 사실, 문서 간 충돌, 가정, 미확인을 구분한다. 근거는 파일·행/쪽,
   답변 시각 또는 허용된 공개 1차 자료의 URL·버전으로 연결한다.
4. 출력이나 안전한 동작을 바꾸는 질문만 실무자에게 묶어 묻는다.
   근거 있는 기본값으로 되돌릴 수 있는 구현은 진행하되 선택과 영향을 기록한다.
   단위·권한·업무 정책이 불명확한 결과를 임의로 정상 결과로 확정하지 않는다.
5. 정상 입력 하나와 빈 값·경계·중복·모순 등 중요한 반례를 실제 규칙으로 만든다.
   전문 용어를 입력→처리→출력 예시로 설명하고 구현 전에 기대 결과를 확인한다.
6. 핵심 경로를 먼저 연결한다. 도메인 규칙은 식별 가능한 함수·설정·계약에 모아
   새 답변으로 정책이 달라져도 변경 위치와 영향을 찾을 수 있게 한다.

필요하면 toolkit의 `templates/DOMAIN_BRIEF.md`와 `DATA_CONTRACT.md`를 사용한다.
파일이 없으면 기존 작업 문서에 같은 최소 정보만 남긴다. 양식 작성 자체를 목표로 삼지 않는다.

외부 자료가 필요하면 먼저 제공 자료에서 빈틈을 특정한다. 플랫폼이 허용하는
공개 자료 조회 방식만 사용하고 문제·코드·개인정보를 외부 검색어로 보내지 않는다.
Context7은 주로 소프트웨어 라이브러리 자료다. 전문 업무 규칙을 확인한 근거로 대체하지 않는다.

반환: 확정한 목표와 규칙, 구현을 바꿀 미확인 사항, 최소 수용 사례, 다음 실행 한 가지.
