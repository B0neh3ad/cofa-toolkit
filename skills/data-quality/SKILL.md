# 데이터 의미와 무결성 확인

- 원본 파일은 보존한다. 형식·인코딩·크기·행/열 수·스키마를 필요한 범위에서 확인한다.
  민감한 원문을 대량 출력하지 않고 집계와 비식별 최소 사례로 문제를 설명한다.
- 필드의 자료형과 업무 의미를 분리한다. 식별자의 앞자리 0, 빈 값/0/false,
  시간대·날짜 경계, 단위·통화·반올림 시점, 비율의 분모와 백분율 표기를 확인한다.
- 범위·누락·중복·참조 무결성·상태별 개수를 실제 요구와 비교한다.
  관찰된 이상치를 자동 삭제하거나 평균·0으로 대체하지 않는다. 정책 근거를 확인한다.
- 조인 키의 유일성과 조인 전후 행 수를 확인한다. 다대다 증폭, 누락 조인,
  집계 전/후 중복 제거, 누적값 재합산과 순서 의존성을 점검한다.
- 검증된 업무 규칙으로 불변조건을 정한다. 예: 해당 의미가 성립할 때만 부분합=전체합,
  단위 변환 왕복 오차 범위, 상태 전이의 허용 경로, 입력과 제외·출력 건수의 대응.
  정렬·중복·행 순서를 바꿔도 결과가 같다는 가정을 모든 과제에 강제하지 않는다.
- 표본 점검과 전체 데이터 검증을 구분한다. 전체 처리를 못 했으면 범위와 이유를 남긴다.
  작은 데이터에서 사람이 계산한 기대값과 실제 파이프라인을 비교한다.
- 파일 저장 후 다시 읽어 스키마·행 수·핵심 집계·형식이 유지되는지 확인한다.
  JSON의 NaN/Infinity, 날짜 직렬화, CSV 구분자·따옴표, Excel 수식으로 해석되는
  출력과 단순 문자열의 차이 중 실제 출력에 해당하는 것을 다룬다.
- 설치된 표준 도구와 기존 라이브러리를 우선 사용한다. 필요가 생긴 패키지만 추가한다.
  수치의 정밀도·데이터 크기·메모리·실패한 행의 처리를 실제 제한과 연결한다.

업무 정책은 `DATA_CONTRACT.md`, 실제 명령·건수·검증 범위는 WORKLOG에 기록한다.
양식이 없으면 기존 문서에 최소 정보만 남긴다. DB 도구의 SELECT 성공은 업무 정책이나
전체 데이터 정합성의 증거가 아니다. 원본 DB에는 기본적으로 읽기 전용으로 접근한다.

반환: 스키마와 의미, 발견한 품질 문제와 근거, 채택한 처리 정책, 검증 결과와 미확인 범위.
