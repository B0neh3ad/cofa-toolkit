AI 협업 과제용 툴킷 v3

이 폴더는 새로 작성한 범용 지침, 템플릿, 연습용 코드만 담고 있습니다.
공식 시험 자료, 메일, 개인 접속 링크, 실제 시험 문제는 포함하지 않았습니다.
공개 저장소: https://github.com/B0neh3ad/cofa-toolkit
시험 환경에서의 반입·실행은 직접 확인해야 합니다.

읽는 순서
0. PRECHECK_15MIN.txt: 사전 체험의 시간 배분과 templates/ENVIRONMENT.md 기록 양식
1. START_EXAM.txt: 처음 한 번의 요청과 이후 짧은 후속 요청
2. docs/PARALLEL_FAST_PATH.md: 반복 지침·의존성·파일 소유권·워크트리·도착순 통합
3. templates/AGENTS.md와 WORKLOG.md: 공통 규칙과 현재 상태를 나누는 최소 양식
4. docs/WORKFLOW.md: 검증과 실행 근거를 남기는 상세 방법
5. practice/PRACTICE.txt: 기본 20분 과제와 반복 검증·인계 연습
   practice/browser/README.md: 설치 없는 3분 서버·Browser·버튼·저장 연습
6. PROMPTS.txt와 REFERENCES.json: 필요한 요청과 자료만 선택해서 참고

시험 중 최소 구성
- 공통 규칙은 AGENTS.md, 이번 요구와 상태는 WORKLOG.md에 유지합니다.
- 병렬 구현에 필요할 때 CONTRACT.md와 작업판을 추가합니다. 모든 양식을 만들 필요는 없습니다.
- 작업자에게는 디렉터리·브랜치·기준·수정 범위·완료 확인을 전달합니다.
- 확정된 규칙을 매번 다시 입력하거나 단계마다 재승인받는 대기를 줄입니다.
- 작업이 완료되면 다른 작업자를 기다리지 말고 검토·통합합니다. 통합 자체는 한 명이 맡습니다.

v3의 추가 도구와 Skill
- scripts/worktree_lab.py: 새 임시 저장소에서 두 워크트리의 병렬 수정·커밋·통합·전체 검증을 연습합니다.
  실제 Git을 쓰지만 정해진 예제 수정이며 Codex나 AI 서브에이전트를 실행하지 않습니다.
  기존 저장소·전역 설정·원격은 바꾸지 않고 연습 결과를 보존합니다.
- skills/parallel-delivery: 의존성과 파일 소유권을 정해 완료된 결과부터 통합합니다.
- skills/session-handoff: 검증된 단위에서 다음 세션이 이어갈 짧은 상태 기록을 만듭니다.
- templates/CONTRACT.md, PARALLEL_PLAN.md, WORKER_BRIEF.md: 필요한 경우에만 사용합니다.

기존 검증 도구
- scripts/run_checks.py: 명시한 명령을 실행하고 종료 코드, 소요 시간, 출력,
  파일 SHA-256, 검증 종류를 남깁니다. 수정 전후 같은 검증 결과를 비교할 수 있습니다.
- scripts/scan_secrets.py: 지정한 파일의 일부 자격증명 패턴을 검사합니다.
  일치한 값은 출력하지 않습니다. 누락 가능성이 있어 수동 검토를 대체하지 않습니다.
- skills/csv-order-contract: 주문 CSV의 검증·중복·반올림 정책을 검토하는
  도메인 예시입니다. 실제 과제가 다르면 정책과 검증을 먼저 바꿉니다.
- templates/AI_COLLABORATION.md: 실제 위임과 수정, 실행 증거를 연결할 선택 양식입니다.
- tests/test_tools.py는 위 도구의 테스트입니다. practice/test_orders.py는
  결함이 있는 연습 프로그램의 테스트이므로 처음에는 실패해야 합니다.

빠른 실행 - 이 폴더에서
  python3 -m unittest discover -s tests -v
  python3 scripts/run_checks.py --config practice/checks.json --stage baseline
  python3 scripts/worktree_lab.py
두 번째 명령은 초기 결함과 기대 출력 불일치를 검출하여 종료 코드 1을 반환합니다.
실패를 보존하는 정상적인 동작입니다. 자세한 수정 전후 연습은 docs/WORKFLOW.md를 봅니다.
세 번째 명령은 Git이 설치된 준비 환경에서 실행하는 별도 연습입니다.

브라우저 연습 - 이 폴더에서 실행 후 서버 터미널 유지
  python3 -m http.server 3000 --bind 0.0.0.0 --directory practice/browser
플랫폼 Browser에서 실제 포트와 경로 /를 입력합니다.
practice/browser/README.md의 추가·완료·삭제·새로고침 체크리스트로 직접 확인합니다.

실제 과제에 적용
- 과제 README와 기존 AGENTS.md를 먼저 확인합니다. 템플릿으로 덮어쓰지 않습니다.
- 문서 파일명과 제출 경로는 실제 과제의 요구를 따릅니다.
- AGENTS.md는 지속 지침이고, WORKLOG.md는 상태 기록입니다.
  WORKLOG.md나 PLANS.md가 특별한 시스템 기능을 자동으로 켜지는 않습니다.
- skills/의 각 폴더를 프로젝트의 .agents/skills/ 아래에 복사하면
  해당 경로를 지원하는 Codex에서 발견할 수 있습니다. 발견 여부는 직접 확인합니다.
  파일을 설치하지 않아도 Codex에게 SKILL.md의 경로를 지정해 읽게 할 수 있습니다.
- Skill은 지침이며, 프로그램이나 보안 격리가 아닙니다.
- 전역 설정, 기존 모델, 승인 정책은 이 툴킷으로 변경하지 않습니다.
- 검증 도구는 설정 파일의 명령을 실제 실행합니다. 설정을 먼저 검토하고,
  실행 권한이나 플랫폼 제한을 우회하는 샌드박스로 생각하지 않습니다.
- 명령 인자에 자격증명을 넣지 않습니다. 로그의 자동 마스킹은 일부 패턴만
  처리하므로, 수집할 출력 자체를 최소화하고 결과를 확인합니다.
- 실행 로그는 기본적으로 과제 안의 .evidence/에 생성됩니다. 시험 작업 기록으로
  로컬에 보존하고, 공개 저장소에는 올리지 않습니다.

공개 배포가 필요한 환경
- 이 폴더만 별도의 빈 공개 저장소에 준비합니다. 상위 폴더의 자료를 올리지 않습니다.
- 저장소 URL과 사용할 커밋을 미리 기록합니다.
- 시험 중 반입은 해당 플랫폼에서 허용하는 clone/다운로드 방식만 사용합니다.
- 이 로컬 폴더를 준비했다는 사실만으로 반입이 완료되지는 않습니다.
- 공개 범위와 공개 유지 기간은 해당 시험의 최신 안내를 따릅니다.
- 과제 중 생성한 코드, 문제, 데이터, 작업 기록은 공개 저장소로 보내지 않습니다.

검증과 보안
- 코드 실행 기록과 결과를 근거로 완료를 판단합니다.
- .gitignore는 커밋 제외 규칙입니다. AI나 프로세스의 파일 읽기를 차단하지 않습니다.
- 비밀값은 제공된 안전한 저장 방식으로 다루고, 로그나 프롬프트에 원문을 넣지 않습니다.
- 외부 저장소는 필요한 파일과 의존성, LICENSE, 자동 실행 스크립트를 먼저 검토합니다.
- 연습 코드는 의도적으로 결함이 있습니다. 그대로 실제 결과물에 사용하지 않습니다.

새로 작성한 이 폴더의 파일은 LICENSE의 MIT 조건으로 사용할 수 있습니다.
REFERENCES.json에 연결된 외부 자료는 각각의 라이선스와 이용 조건을 따릅니다.
