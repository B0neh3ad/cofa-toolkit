# 업무별 준비 연습

아래는 연습용 설계 예시다. 실제 시험 주제나 실행 완료 보고가 아니며 검증 결과는 과제를 수행한 뒤 채운다.

## 제조 데이터의 불량률 분석

목표는 설비별 품질을 설명할 수 있는 집계와 보고서다. 검사 수·불량 수의 단위, 중복 행의 뜻, 제외할 상태와 기준 기간을 먼저 확인한다. 완료 조건에는 총합의 분모와 제외 건수를 넣는다.

반복 검토용 Skill에는 스키마·분모·중복 규칙과 데이터 보존식을 넣는다. 행별 비율의 단순 평균과 합산 불량 수/합산 검사 수를 구분하고, 0 분모·결측·잘못된 단위를 확인한다. 입력 건수와 포함·제외 건수는 서로 겹치지 않는 분류라면 일치해야 한다.

읽기 전용 검토자는 집계식과 제외 기준을 조사하고 주 에이전트는 집계와 보고서 출력을 만든다. 잘못된 분모를 발견했다면 재현 데이터를 고정하고 수정 전후 같은 검증을 실행한다. 실제 CSV를 읽는 CLI와 보고서의 수치가 일치하는지도 확인한다. 한계에는 제외 데이터와 기간·표본의 제약을 적는다.

## 외부 API를 사용하는 업무 처리

먼저 외부 호출이 실제 요구인지, 제공 환경에서 허용되는지 확인한다. 업무 규칙과 호출 어댑터의 경계를 정하고 성공·타임아웃·호출 제한·잘못된 응답의 처리를 정한다. 상태를 바꾸는 호출이면 재시도와 중복 요청의 효과를 명시한다.

작은 검토 지침은 오류 분류와 재시도 대상, 중복 부작용 검증에 집중시킨다. mock으로 경계 오류를 재현하고, 허용된 실제 환경에서는 주 흐름의 연동을 별도로 확인한다. mock 통과만으로 실제 인증이나 서비스 제한이 확인되었다고 쓰지 않는다.

검토자에게 오류를 삼키는 경로와 중복 실행 가능성을 맡기고 실제 변경은 담당 파일을 나누거나 순차 수행한다. 동시 요청 결함을 찾았다면 그 요청 조건을 고정한 검증으로 수정 전후를 확인한다. 실제 연동이 금지되거나 제공되지 않으면 대체 AI·개인 키를 추가하지 않고 미검증 경계를 기록한다.

## 자료를 근거로 업무 보고서 작성

독자·판정 기준·자료 시점을 정한다. 수치 추출과 정책 적용을 분리하고 각 결론을 원문 위치나 데이터 행으로 연결한다. 자료 부재와 문제가 없다는 결론을 구분한다.

반복 지침은 근거 없는 결론, 누락 항목, 서로 다른 시점의 수치를 혼합하는 오류를 찾는 데 사용한다. 검토자는 결론과 근거를 대조하고 작성자는 확인된 사실과 해석을 구분한다. 계산 오류를 찾으면 원자료를 고정하고 계산 검증을 재실행한다. 파일을 실제로 열거나 생성 명령을 실행한 범위도 기록한다.

인계에는 사용한 원자료 버전, 확정한 판정 기준, 확인하지 못한 항목과 다음 조사 대상을 적는다. 설명할 때는 자동 계산한 부분과 사람 판단이 필요한 부분을 구분한다.

## 병렬로 분해할 때

| 주제 | 먼저 함께 정할 것 | 겹쳐 진행할 작업 | 통합에서 확인할 것 |
| --- | --- | --- | --- |
| 제조 분석 | 스키마·집계식·제외 규칙 | 계산 구현, 독립 검증 입력 작성, 보고서 틀 | 실제 집계와 보고 수치의 일치 |
| API 서비스 | 요청·응답·오류·부작용 계약 | 어댑터 구현, 소비 UI, 계약 테스트 | 실제 호출·화면·실패 처리의 연결 |
| 보고서 | 자료 기준 시점·추출 형식·판정 규칙 | 수치 추출, 정책 검토, 보고서 구성 | 결론마다 근거와 계산이 연결되는지 |

모든 작업자가 공용 문서를 수정하지 않게 한다. 표의 분리는 예시이므로 실제 의존성을 확인한다.
계약이 바뀌거나 같은 파일·자원을 함께 바꿔야 하면 역할을 다시 나누고 짧게 순차 처리한다.
