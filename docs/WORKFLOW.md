# AI 협업 작업과 실행 증거

제한된 시간에 완성할 결과를 정하고, AI가 만든 변경을 검증 가능한 작은 단위로 다룬다. 도구 설치나 문서 작성의 양보다 실제 작업을 재현하고 설명할 수 있는 상태가 중요하다. 아래 여섯 항목은 자기 점검용이며 특정 시험의 공식 배점표가 아니다.

## 여섯 가지 점검

| 항목 | 실제로 할 일 | 확인할 근거 |
| --- | --- | --- |
| 검증 | 중요한 결함의 실패를 재현하고 수정 뒤 같은 조건으로 실행 | 실패·통과 로그, 입력, 코드 상태 |
| 상태 보존 | 확정 정책·현재 상태·다음 명령을 파일에 갱신 | 새 세션이 실제 파일과 대조해 재개 가능 |
| 구조와 경계 | 업무 규칙과 I/O 경계를 확인하고 오류와 부작용을 다룸 | 관련 함수, 실패 경로, 필요한 동시성 검증 |
| 정보 보호 | 비밀값의 코드·로그·프롬프트 노출을 줄임 | 값 없이 위치를 알리는 검사와 수동 검토 |
| 도구 선택 | 반복 업무에 맞는 도구를 선택하고 불필요한 도구를 제외 | 실제 실행 결과와 줄인 작업 |
| 위임 | 역할·수정 범위·종료 조건을 정하고 결과를 직접 확인 | 실제 위임 기록과 반영 파일·검증 연결 |

단순 CSV 요약에 Controller, Service, Repository를 모두 만들 필요는 없다. 읽기·검증·계산·출력의 책임과 오류 처리가 분명하면 충분할 수 있다. 외부 API가 있으면 호출을 좁은 경계로 감싸고 시간 초과·잘못된 응답·호출 제한·재시도 시 중복 부작용을 검토한다. 상태를 바꾸는 작업에는 필요한 원자성이나 동시성 정책을 적용한다.

기본 기록은 WORKLOG.md 한 파일로 시작한다. AI_COLLABORATION.md는 협업 증거를 따로 제출하거나 확인할 필요가 있을 때 선택한다. 템플릿 파일명은 과제의 필수 파일명을 대체하지 않는다.

## 3시간 안에 적용하기

반복 지침과 병렬 운영의 빠른 경로는 [속도와 병렬화](PARALLEL_FAST_PATH.md)를 사용한다.

| 경과 시간 | 목적 | 완료 조건 |
| --- | --- | --- |
| 0~15분 | 요구·기존 동작·환경 확인 | 중요한 모호함과 현재 실패를 파악 |
| 15~25분 | 작은 계약·완료 조건·검증 경로 확보 | 실행 가능한 작업과 소유 범위가 정해짐 |
| 25~60분 | 핵심 기능 병렬 구현·도착순 통합 | 입력부터 최종 출력까지 한 번 연결 |
| 60~110분 | 관련 실패·경계 검증과 수정 | 실제 결함 재현·수정·재실행 근거 |
| 110~140분 | 남은 필수 기능과 범위 조정 | 선택 기능보다 필수 완성과 검증 우선 |
| 140~160분 | 통합 마무리·문서 대조·설명 | 실제 흐름·선택·한계를 본인이 설명 |
| 160~170분 | 최종 확인과 제출 준비 | 최종 디렉터리·실행·저장 상태 확인 |
| 170~180분 | 저장·경로·제출 확인 | 제출을 마치고 다음 단계 안내 확인 |

하네스나 Skill을 만드는 시간은 줄어드는 반복 작업과 비교한다. 기존 명령이 충분하면 그것을 쓴다. 서브에이전트는 독립된 조사나 검토에서 시작하고 공유 파일 동시 수정을 피한다. 확인하지 못한 토큰 수나 비용 절감 수치를 만들어 적지 않는다.

## 실행 기록 도구

툴킷 루트에서 다음을 실행한다. Python 3.9 이상 표준 라이브러리만 사용한다.

```bash
python3 -m unittest discover -s tests -v
python3 scripts/run_checks.py --config practice/checks.json --stage baseline
```

첫 명령은 도구 자체의 테스트다. 두 번째는 결함이 있는 연습 프로그램을 검사하므로 초기 종료 코드 1이 정상이다. 테스트 실패뿐 아니라 CLI가 종료 코드 0으로 잘못된 JSON을 출력하는 경우도 검출한다.

출력 마지막 줄의 manifest.json 경로를 보존한다. 각 실행은 새 폴더에 검증 종류·명령·종료 코드·소요 시간·결과, 실행 전후 파일 SHA-256, 일부 패턴을 마스킹한 로그를 남긴다. 실행 중 파일이 바뀌었는지도 기록한다.

회귀 검증을 추가한다면 수정 전 그 검증이 실패하는 것을 먼저 확인한다. 같은 테스트·입력·정책을 유지한 채 구현을 수정한 뒤 다시 실행한다.

```bash
python3 scripts/run_checks.py --config practice/checks.json --stage verify --baseline "수정_전_실행의_manifest.json_실제_경로"
```

따옴표 안은 앞서 출력된 실제 경로로 바꾼다. 설정이 달라지면 비교를 거절한다. fixed_paths나 기대값이 바뀌거나 실행 도중 파일이 달라지면 동일 조건의 실패→통과로 처리하지 않는다. 테스트를 정당하게 바꿔야 하면 변경한 테스트로 새 기준선을 만든다.

failed_to_passed_checks는 실행 상태의 변화다. 이것만으로 실제 제품 버그를 AI가 발견했다는 사실까지 증명하지는 않는다. 원인, 실제 발견 기록, 변경 함수와 결과를 사람이 대조한다. 인프라 설정 수정으로 실행이 복구된 경우도 제품 로직의 결함 수정과 구분한다.

### 다른 과제에 맞추기

파일 경로와 실행 디렉터리는 설정 파일이 있는 폴더를 기준으로 한다. 각 명령은 argv 배열이며 shell을 거치지 않는다. 파이프나 리다이렉션 문법 대신 별도 검증 프로그램 또는 실제 실행 파일을 지정한다.

- source_paths: 구현과 직접 관련된 파일. 해시는 지정한 범위만 보증한다.
- fixed_paths: 같은 조건 비교에서 유지해야 할 테스트, 입력, 정책 문서.
- checks: id, kind, argv, timeout_seconds와 선택적인 requirements.
- stdout_json_file: stdout을 비교할 기대 JSON. 해시·비교 대상에 자동 포함된다.
- kind: unit, local-integration, mock, external-integration, static 중 실제 범위.

설정한 명령은 현재 권한으로 실제 실행된다. 이 도구는 보안 격리 기능이 아니며 외부 접근 허용 여부를 결정해주지 않는다. 플랫폼이 금지한 도구·API·업로드를 설정에 넣지 않는다.

### 검증 범위

| 기록 | 확인한 것 | 여전히 확인해야 할 것 |
| --- | --- | --- |
| 단위 테스트 | 함수나 규칙의 동작 | 실제 입출력·연동·운영 설정 |
| mock | 가정한 응답에 대한 처리 | 실제 서비스의 응답·인증·제한 |
| 로컬 통합 | 실제 파일·프로세스·CLI 등 로컬 경계 | 사용하지 않은 외부 서비스 |
| 실제 외부 연동 | 허용된 환경의 실제 호출과 처리 | 호출하지 않은 실패·규모·운영 조건 |
| 직접 확인 | 수행한 사용자 동작과 관찰 | 자동 회귀나 관찰하지 않은 경로 |

kind를 external-integration으로 쓰는 것만으로 실제 호출을 증명할 수 없다. 대상과 실행 경로, 비밀값을 뺀 응답 형태나 요청 추적 근거를 확인한다. 실제 연동이 필수이고 환경에서 허용하면 수행한다. 연동이 없거나 금지되어 있으면 임의 API 키나 외부 서비스를 추가하지 않고 미검증 경계를 밝힌다. CSV 과제의 실제 CLI·파일 검증도 의미 있는 로컬 통합 검증이다.

## 비밀값 검사

```bash
python3 scripts/scan_secrets.py practice/orders.py practice/test_orders.py
```

지정한 파일 또는 디렉터리 안의 일부 개인키·키 패턴·자격증명 대입·URL 패턴을 찾는다. 발견 시 값 대신 파일·행·규칙만 출력하고 종료 코드 1을 반환한다. 읽기 오류는 2다. 추측 패턴에 의존하므로 오탐과 누락이 있고 결과 0은 비밀값이 없다는 보증이 아니다. 심볼릭 링크 입력은 거절하며 하위 링크는 따라가지 않는다. 작은 텍스트 소스와 로그를 지정하고 대용량·바이너리 폴더 전체를 넣지 않는다.

로그 마스킹도 일부 패턴만 다룬다. 명령 인자에 비밀값을 넣지 말고 출력 자체를 최소화한 뒤 파일을 확인한다. 환경변수나 비밀 저장 기능은 하드코딩을 줄이지만 읽기 권한과 로그 노출까지 자동 해결하지 않는다. .gitignore도 AI의 읽기 차단 기능이 아니다.

## 도메인 Skill과 인계

범용 Skill은 시작점이다. 같은 검토를 반복할 때 입력 스키마, 중요한 업무 규칙, 실패 사례와 검증 명령을 좁은 Skill에 넣는다. csv-order-contract는 주문 CSV의 유효성·중복 선점·금액 반올림을 검토한다. 다른 데이터에서는 그대로 가정하지 않고 과제의 정의를 먼저 읽는다.

사용한 Skill의 효과는 파일 개수가 아니라 실제 발견·수정·검증으로 확인한다. 누락된 입력 검증을 조사하게 하고 결함이 있다면 재현 검증을 추가한 뒤 수정 전후를 실행한다. 발견이 없다면 없다고 기록한다. 문서를 읽은 사실만으로 버그 발견을 주장하지 않는다.

세션을 바꾸기 전 최신 WORKLOG.md에 확정 정책, 마지막 확인 실행, 현재 파일 상태, 남은 필수 작업, 다음 명령을 남긴다. 새 세션은 그 파일과 실제 구현을 대조하고 필요할 때 핵심 검증을 실행한다. 기록이 오래되었다면 먼저 갱신한다.

설명은 입력→규칙→외부 경계 또는 저장→출력 순서로 한다. 구조 선택에는 검토한 대안과 비용을, 협업 주장에는 실제 반영 위치를, 완료 주장에는 실행 기록을 연결한다. AI가 금지된 평가 단계에서는 Skill이나 설명 보조도 사용하지 않는다.
