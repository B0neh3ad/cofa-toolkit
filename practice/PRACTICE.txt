20분 서브에이전트 연습: 주문 CSV 요약기

이 과제는 새로 만든 연습 예제이며 실제 시험의 예상 정답이나 복원 문제가 아닙니다.
Python 3 표준 라이브러리만 사용합니다. orders.py에는 의도적인 결함이 있습니다.

업무 요구사항
- CSV를 읽어 팀별 완료 주문 금액을 JSON으로 출력합니다.
- summarize(path)와 CLI 사용 방법은 유지합니다.
- status가 completed인 행만 집계합니다. cancelled와 나머지 상태는 제외합니다.
- order_id와 team은 양끝 공백을 제거한 뒤 비어 있으면 제외합니다.
- quantity는 양의 정수만, unit_price는 유한한 0 이상의 십진수만 허용합니다.
  이 조건을 만족하지 않는 행은 제외합니다.
- 유효한 completed 주문에서 order_id가 같으면 첫 행만 반영합니다.
  제외한 행은 ID를 선점하지 않습니다. 중복을 판단하기 전에 유효성을 확인합니다.
- 각 주문의 quantity × unit_price를 소수 둘째 자리로 사사오입(ROUND_HALF_UP)한 뒤 합칩니다.
- 출력 값은 소수점 아래 두 자리를 유지하는 문자열입니다. 팀 키는 정렬합니다.
- 헤더만 있는 CSV의 결과는 빈 JSON 객체입니다.
- 필수 헤더 누락이나 읽을 수 없는 파일은 정상 결과로 위장하지 말고 오류로 처리합니다.

0~3분: 기준선 확인
이 폴더에서 실행합니다.
  python3 -m unittest -v
  python3 orders.py orders.csv
v2는 계약 검토로 빠진 검증 2개를 추가하여 총 7개입니다.
초기 상태는 테스트 1개 성공, 5개 실패, 1개 오류가 예상됩니다.
도구 자체 테스트(tests/test_tools.py)의 통과 결과와 구분합니다.
샘플 출력은 EXPECTED.json과 달라야 합니다. 고치기 전 기록을 남깁니다.

3~7분: Codex 시작과 위임
이 폴더에서 codex를 시작한 뒤 아래 요청을 입력합니다.

PRACTICE.txt를 기준으로 서브에이전트 2개를 사용해줘.
A는 orders.py의 업무 규칙 위반과 재현 입력을 조사해줘.
B는 test_orders.py에서 빠진 검증과 중요한 실패 조건을 조사해줘.
두 에이전트 모두 파일 수정은 하지 마. 두 결과를 기다린 다음
확인된 결함, 의심 사항, 수정 우선순위를 구분해 요약해줘.
기능을 사용할 수 없다면 같은 역할을 순차 검토해줘.

기능이 있다면 /subagents로 상태를 확인합니다. 명령이 없는 버전은 /help를 확인합니다.
시험용 환경에서는 기능을 켜기 위해 업데이트하거나 관리 설정을 바꾸지 않습니다.

7~15분: 본인이 이해한 뒤 수정
원인과 정책을 직접 확인한 다음 요청합니다.
  합의한 정책을 유지하며 orders.py를 수정해줘. 확인된 검증 누락 중
  중요한 것은 test_orders.py에 추가해줘. 실제 테스트와 샘플 CLI를 실행하고,
  결과와 한계를 보고해줘. 요구사항을 낮춰 통과시키지 마.

15~20분: AI 없이 직접 확인하고 설명
- 테스트를 다시 실행하고 EXPECTED.json과 실제 샘플 출력을 비교합니다.
- cancelled 행을 바꾸어도 합계에 영향이 없는지 확인합니다.
- 같은 유효 주문을 복제해도 합계가 변하지 않는지 확인합니다.
- 아래 질문에 코드와 AI 답변을 보지 않고 말로 답합니다.
  1. 왜 단순 float 대신 정확한 십진수 정책이 필요한가?
  2. 왜 중복 제거 전에 유효성을 확인하는가?
  3. 입력부터 JSON까지 어떤 순서로 처리하는가?
  4. 어떤 입력을 제외했고 무엇을 검증하지 못했는가?
  5. 큰 파일이라면 시간과 메모리 사용은 어떻게 변하는가?
  6. 두 에이전트의 결과 중 무엇을 직접 확인했는가?

완료 기준은 자연어 설명, 실제 코드, 실행 결과가 일치하는 것입니다.

추가 10~15분: 반복 검증과 세션 인계
- 툴킷 루트에서 실행합니다.
  python3 scripts/run_checks.py --config practice/checks.json --stage baseline
- 종료 코드 1과 함께 출력되는 manifest.json 경로를 보존합니다.
- ../skills/csv-order-contract/SKILL.md를 읽게 하고, 현재 정책과 실제 코드의 차이를
  검토하게 합니다. 이 상대 경로는 practice 폴더에서 보았을 때의 경로입니다.
- 구현을 수정한 뒤 같은 설정으로 --stage verify --baseline 옵션에 앞선 실제
  manifest.json 경로를 주어 실행합니다. 자세한 명령은 docs/WORKFLOW.md를 봅니다.
- 테스트·입력·기대값을 바꿔야 한다면 바꾼 검증으로 새 기준선을 만듭니다.
- 기존에 없던 두 검증은 공백 정규화와 '행이 없어도 필수 헤더 검증'입니다.
  첫 유효 주문 정책은 행 순서에 의미가 있으므로 무조건 섞어도 같은 결과라는
  검증을 추가하지 않습니다. BOM 지원은 별도 정책 확인 없이 새 필수조건으로 만들지 않습니다.
- WORKLOG에 코드 상태, 확인한 실행, 확정 정책, 다음 명령을 적습니다.
- AI 사용이 허용되는 연습 단계에서만 새 세션으로 바꾸어 이 파일들과 실제 코드로
  재개할 수 있는지 확인합니다. 서술형 평가 중에는 이 연습을 하지 않습니다.
